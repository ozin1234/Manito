# K-ROAD 사진 제보 세부 유형·속도 검증 (2026-11-24)

## 범위와 판정 기준

실제 `gemini-3.5-flash-lite`를 현재 `/v1/assistant/chat` 서버 경로로 호출했다. 평가 전 사람이 사진을 보고 `intent`, 분야, 세부 유형, 추가 확인 필요 여부(`ready`)를 정답표에 기록했다. 서로 다른 공개 사진으로 1차 13장, 2차 독립 사진 13장, 보완 후 추가 사진 3장을 평가했다. 같은 사진 재호출 3건은 독립 표본 수에서 제외했다. 사진은 Wikimedia Commons의 해외 사례이며 강원 주민의 실제 제보 사진이 아니다. 출처·정답표·행별 원시 결과는 `docs/evaluation/photo-20261124/`에 있다.

분야 `living/road/safety` 아래 구체 유형 12개를 **각각** 확인했다. `other_living/other_road/other_safety`는 범위가 정해지지 않은 기타 항목이므로 자동 확정하지 않고 사람의 확인이 필요하다. 유형 정답은 `intent+분야+issueType` 일치이며 `no_issue`에서는 분야 선택을 채점하지 않는다. 완전 일치는 여기에 `ready` 일치를 더한다. 200 응답이 없는 사례는 오답으로 꾸미지 않고 별도 실패로 센다. 사용자 GPS, 촬영, 압축, 휴대폰 업로드, 현장 정답 검수, 기관 접수는 시험에 포함되지 않았다.

1차에는 쓰러진 가로등을 일반 시설 파손으로 뭉뚱그렸고, 단순히 젖은 도로 옆 암벽을 낙석으로 잘못 제안했다. 이를 명시적으로 구분하도록 지침을 수정하고 **같은 사진**으로 재확인했을 때 각각 가로등 파손과 문제 없음으로 답했다. 이 재호출은 2차 검증 점수에 더하지 않았다. 1차에서 벤치 사진 1건은 공급자 503으로 실패했다.

2차 실패를 보고 도로 가장자리 유실과 실제 낙석을 구분하고, 경미한 보도 균열의 제보 준비 여부를 확인하도록 지침을 추가했다. 그 뒤 **새** 구부러진 교통 방호 펜스, 다른 보도 파손, 빗물이 고인 도로 사진 3건에서 기대 유형과 준비 여부가 모두 일치했다. 사진당 2.921~3.304초였다. 이 3건은 수정 확인이지 2차 13건의 점수를 고쳐 쓴 결과가 아니다. 2차에서 발생한 침수 사진의 형식 오류 원인은 원본 모델 출력이 저장되지 않아 특정할 수 없다. 앱은 실패를 사용자에게 보여주고 임의의 제보를 저장하지 않는다.

최종 지침을 **같은 2차 사진 13장**에 다시 적용한 회귀 실행에서는 11건 정상 응답, 유형 일치 10/11, 유형·준비 여부 완전 일치 9/11, 형식 오류 2건이었다. 정상 응답 p50/p95는 2.773/6.485초였다. 침수 사진의 형식 오류가 재현됐고 정상 도로도 한 번 형식 오류가 났다. 훼손된 가드레일은 이번에는 낙석 대신 `road_damage`로 분류됐지만 기대한 `safety_facility`는 아니었다. 같은 사진이 호출마다 다른 결과를 낸다는 근거이므로 이 재호출은 독립 검증에 합산하지 않았다.

원인 탐색을 위해 침수·정상 도로·가드레일 사진을 다시 호출했을 때 세 건 모두 응답했지만, 침수는 추가 확인이 필요하다고 했고 정상 도로에는 `road_report/none`이라는 일관되지 않은 조합을 반환했다. 그 조합을 저장 단계에서 거부하고, 정상 도로는 `no_issue/none`으로 답하도록 지침을 추가했다. 최종 코드를 같은 3장에 재호출했을 때 정상 도로는 `no_issue/none`이었으나 침수의 준비 여부와 가드레일 유형은 여전히 사전 정답과 달랐다. **혼합 장면의 가드레일 구분과 얕은 침수의 준비 여부는 해결됐다고 주장할 수 없다.**

## 구현 변경

- 모델 출력의 구체 유형을 저장 전 검증하고, 기타 3종은 `ready=true`로 자동 확정하지 않도록 서버에서 거부한다.
- `issueType=none`인데 `intent=road_report`인 모순된 응답도 저장하지 않는다.
- 가로등과 일반 생활 시설, 훼손된 교통 안전 시설과 실제 낙석, 침수와 단순 젖은 노면, 미세 보도 균열과 명확한 보행 장애를 구분하도록 사진 판독 지침을 보강했다.
- `services/api/scripts/photo-eval.mjs`는 실제 API 핸들러를 호출하여 유형 정답, 추가 확인 여부, 실패 수, 처리 시간 p50/p95를 행별·유형별로 출력한다. 평가 시 GPS와 공개 확인을 보내지 않았으므로 제보는 게시하지 않았다.

최종 로컬 코드에서 자동 검사 53건, 웹 production 빌드, 저장소의 일반 인증정보 패턴 검사가 통과했다. 자동 검사는 모의 공급자 응답이며 위의 실제 사진 판독 수치와 구분한다. 이 작업본은 로컬 파일이며 원격 GitHub 또는 운영 서버 반영을 확인하지 않았다.

## 아직 필요한 검증

강원 현장 촬영 사진을 **각 구체 유형별 최소 수십 장 이상**, 정상·모호·경계 사례와 함께 독립 검수해 정답표를 만들어야 한다. 지역·시간·기종별로 분리한 별도 시험군에서 유형별 정밀도·재현율, 정상 사진 오탐, 실제 위험 사진 미탐, `ready` 안전성, API 실패율을 계산해야 한다. 사용자 휴대폰에서 촬영·압축·업로드·분석 완료까지 p50/p95도 측정해야 한다. 현재 수치만으로 모든 생활불편을 자동으로 정확히 판별하거나 현장 안전을 보장한다고 표시하면 안 된다. 공식 민원 분류·법 위반·사고 원인·도로 통제 여부는 사진만으로 확정하지 않는다.

## 재현

평가 사진은 라이선스와 출처를 확인한 뒤 `docs/evaluation/photo-20261124/phase*.json`의 상대 경로 `images/`에 내려받아 둔다. 서버 전용 환경변수 `GEMINI_API_KEY`를 설정하고 `node services/api/scripts/photo-eval.mjs <정답표.json>`을 실행한다. 결과에는 키와 이미지 데이터가 쓰이지 않는다. 사진은 소스 ZIP에 포함하지 않았다. 같은 파일을 다시 호출한 결과는 독립 사진 수에 포함하지 않는다.
