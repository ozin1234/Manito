# 사진 판단 응답 형식 오류 수정

## 확인한 원인

운영 `/api/v1/assistant/chat`에서 502가 두 번 발생했고 화면은 `AI_RESPONSE_INVALID`를 표시했다. 기존 로그에는 거절된 필드가 없으므로 해당 운영 두 응답의 원시 판단은 복원하지 못한다.

사용자가 제공한 오류 화면 이미지를 기존 Gemini 모델로 분석해 동일한 실패 경로를 재현했다. 첫 응답은 정상 JSON과 `STOP` 종료였지만 객관식 선택지가 4개였다. 서버는 3개를 초과하면 전체 답변을 거절했다. Gemini에 보낸 JSON Schema에는 배열 개수 제한이 없어 생성 계약과 서버 검증 계약이 달랐다. 재시도 응답에서는 3개가 생성되어 통과했다. 사진 업로드 실패나 키 누락은 아니었다.

원본 현장 사진 파일 대신 제공된 앱 화면 이미지를 사용했으므로 재현 결과를 현장 사진 정확도 평가나 해당 운영 요청의 유일한 원인으로 단정하지 않는다.

## 수정

- 선택지를 2~4개까지 처리하며 4번째 버튼과 답변을 그대로 보존한다. 선택지를 잘라 버리거나 확인 불가 답변을 접수 동의로 바꾸지 않는다.
- Gemini 응답 스키마·시스템 안내·서버 검증에서 배열 개수와 문자 길이 기준을 공유한다. 관찰 최대 6개, 선택지 최대 4개, 근거 ID 최대 8개를 스키마에 명시한다.
- 문자열 길이는 설명으로 안내하고 서버에서 계속 검증한다. [Google 공식 문서](https://aistudio.google.com/docs/structured-output)에 따르면 `maxItems`는 지원하지만 `maxLength`는 생성 중 강제되지 않으므로 서버 검증을 제거하지 않는다.
- 검증 실패 시 1회 재시도에 서버의 거절 항목을 전달한다. 재차 실패하면 사진을 유지하고 오류를 알리며 임의로 접수하지 않는다.
- 운영 로그에는 모델·시도·오류 코드·서버가 정한 거절 항목만 남긴다. 사진·원시 AI 답변·위치·키·접수증은 기록하지 않는다.

미등록 유형·근거 ID·문제 없음·분야/유형 불일치·불확실한 판단의 자동 접수 차단은 유지한다. 모델·API 키·환경변수·DB·프론트엔드 디자인 변경은 없다.

## 검증

- 4개 선택지가 재시도 없이 표시되고 4번째 답변이 AI 문맥·비공개 접수·접수 내역까지 전달되는 회귀 테스트를 추가했다.
- 5개 선택지와 길이 초과 응답은 보완 지시 후에도 잘못되면 접수되지 않는지 검사했다. 로그에 원문이 포함되지 않는 것도 검사한다.
- 기존 직접 접수·중복 방지·비공개 조회·관리자 상태 보호 테스트를 유지한다.
- 실제 Gemini 호출은 격리된 로컬 저장소에서 실시하며 운영 관리자 접수함에 검증용 제보를 만들지 않는다. 최종 전체 테스트·빌드·배포 결과는 PR에 기록한다.
