# 우왓 Gemini 업그레이드 검증

기준: 2026-11-23, `feat/uwat-multimodal-rag`, 원격 main `6f462e4`.

## 1차 검증

- 별도 제보 입력 폼을 대화로 통합했고 기존 지도·경로·GPS·사진 저장 API는 유지했다.
- Gemini 요청은 서버 `GEMINI_API_KEY`만 읽는다. 브라우저 프록시는 내부 API 키를 서버에서 붙인다. `.env.example` 값은 비워 둔다.
- 실제 BM25 검색 자료와 출처, 내부 분류와 공식 기관 지침을 구분한다. 사진 판독 결과가 자동 기관 접수로 이어지지 않는다.
- 확인 토큰·초안 버전·명시적 동의가 있어야 지도에 저장한다. 설명·위치·사진 변경 시 기존 확인을 무효화한다.
- 원본 GROAD와 잇다 환경 파일은 수정하지 않았다. Manito의 별도 볼륨을 사용하며 새 외부 의존성은 추가하지 않았다.

## 기존 Gemini 키 재사용 확인

사용자 요청에 따라 잇다의 로컬 서버 설정·인계 ZIP을 읽었다. Gemini 키 값은 없고 Google TTS 키만 있었다. 해당 Google 키로 Gemini 모델 목록을 조회했으나 HTTP 403 `PERMISSION_DENIED`가 반환되어 Manito에 복사하지 않았다.

이어 `bangjeongwoo1/datathon5`의 현재 main `f3083a95e115`와 전체 10개 브랜치에서 고유 코드·설정·문서 blob 297개를 확인했다. 읽기 오류는 없었고, 사용 가능한 실제 Gemini 인증키를 찾지 못했다. GitHub Actions·배포 환경에 별도로 저장된 비밀 값이나 과거 전체 Git 이력을 조회한 것은 아니다. 키 값·원본 환경 파일 내용은 출력하지 않았다.

## 사용자 제공 키 등록 후 추가 검증

이후 사용자가 직접 제공한 Gemini 키를 무시되는 루트 `.env`에 등록했다. 앞선 기존 키 탐색 결과와 구분되는 후속 결과다. 키 값·원문 환경 파일은 출력하거나 커밋하지 않았다.

- Gemini 모델 목록 실제 조회: 인증 성공.
- `gemini-3.8-flash`: 수요 과다 HTTP 503과 시간초과 관찰. 키 인증 오류로 오인하지 않도록 서버의 5xx 오류를 일시적 장애로 구분하도록 수정했다.
- 로컬 `UWAT_MODEL`을 실제 응답을 확인한 `gemini-3.5-flash-lite`로 설정했다. 코드 기본값은 유지한다.
- 애매한 도로 설명 → 확인 질문: HTTP 200, 약 3.03초.
- 같은 대화의 정치 질문 → 범위 안내·비저장: HTTP 200, 약 1.68초.
- 단색 fixture 이미지 → 위험 확정 없이 판독 한계 응답: HTTP 200, 약 3.36초. 실제 현장 사진의 분류 정확도를 검증한 것은 아니다.
- 현장 확인 설명과 테스트 좌표 → 초안·동의 질문: HTTP 200, 약 2.35초.
- 명시적 확인 후 격리 저장소 저장: HTTP 201, `agencyStatus:not_submitted`. 실제 지도 데이터는 변경하지 않았고 임시 기록은 정리했다.
- 오류 구분 회귀 검사를 추가한 뒤 자동 테스트 27개 통과.
- 키와 서버 오류 처리만 변경해 웹 빌드는 반복하지 않았다. 앞선 빌드 성공 결과와 구분한다.

응답 시간은 소수의 연결 점검 결과이며 성능 지표나 SLA가 아니다. `AQ.` 형식 인증키 패턴도 저장소 검사에 추가했다.

## G-ROAD와 우왓 동시 실행 확인

같은 로컬 웹 서버 5174와 Manito API 8790에서 기존 지도 기능과 Gemini를 동시에 호출했다. 원본 지도 엔진은 조회 용도로만 공유했다.

| 실제 호출 | 결과 |
| --- | --- |
| 웹 페이지·CSS·JavaScript 8개 자산 | HTTP 200, CSS·JS 콘텐츠 유형 확인 |
| 강릉역 장소 검색 | HTTP 200, 실제 장소 결과 3개, 약 2.49초 |
| 강릉역 부근 → 강릉시청 부근 자동차 경로 | HTTP 200, 3,413m·경로 좌표 78개·안내 10개, 약 0.60초 |
| 강릉 부근 지도 타일 | HTTP 200, PNG 39,380바이트, 약 0.24초 |
| 같은 시각 Gemini 도로 상황 대화 | HTTP 200, 추가 확인 질문과 근거 1개, 약 4.42초 |
| 호출 전후 공개 지도 기록 | 동일, 테스트 제보를 공개 저장하지 않음 |

대화 점검 세션은 이 테스트가 만든 UUID 파일만 정리했다. 실제 마이크·기기 GPS를 사용한 것은 아니다. 위 결과는 확인한 실행 범위에서 충돌이 관찰되지 않았다는 뜻이며 모든 기기·모든 요청의 무오류를 보장하지 않는다. 테스트용 웹 서버와 Manito API는 점검 후 중지하며 원본 지도 서비스와 데이터는 보존한다.

## 생활불편·도로·안전재난 분야 연결 검증 (2026-11-23)

- PC 상단/모바일 하단 메뉴를 생활불편·도로·안전재난으로 변경했다. 선택 분야가 지도 목록·건수·우왓 요청·저장 기록에 이어진다. 위험/아차/주의 표시는 별도로 유지한다.
- 1차: 최신 origin/main 6f462e4를 fetch해 비교했다. 기능 브랜치에서 작업했으며 기존 분야 없는 기록은 도로로 읽는다. 기존 원본 저장소·데이터·모델 환경설정은 변경하지 않았다. 의존성·환경변수·데이터 마이그레이션 추가는 없다.
- 2차 모의/자동 검사: 31개 테스트 통과. 분야별 저장, 잘못된 분야 차단, 다른 분야 세션 재사용 거부, 과거 도로 기록 필터, 기존 음성 확인·GPS·사진·지도 API 회귀를 확인했다. TypeScript 검사 및 production 빌드 통과.
- 실제 Gemini: 기존 로컬 gemini-3.5-flash-lite 설정으로 쓰레기 방치(living, 2.49초)와 하천변 침수 우려(safety, 2.51초)를 각각 실행했다. 응답의 분야·내부 운영 근거·질문 또는 위치 확인 단계를 확인했다. 별도 임시 저장소를 사용했고 공개 기록은 생성하지 않았으며 임시 대화는 정리했다. 두 문장에 대한 연결 확인이며 사진 판독 정확도 평가가 아니다.
- 로컬 HTTP: 5174 화면의 세 메뉴 순서·기본 도로 선택을 HTML에서 검사했다. 페이지·CSS/JS 자산 5개가 200, assistant configured=true, 잘못된 topic 요청은 400 INVALID_TOPIC이었다. Manito API만 재빌드했고 기존 GROAD 지도 서비스는 유지했다.
- 현재 도구로 새 화면의 브라우저 시각 검사는 수행하지 못했다. 실기기 화면·마이크·GPS 검증을 완료했다고 주장하지 않는다. 공개 배포·GitHub 푸시·병합은 수행하지 않았다.
