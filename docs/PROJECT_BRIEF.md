# Manito 프로젝트 기획서

## 확정 사항

- 프로젝트명: Manito
- 아동급식카드 프로젝트와 별개인 새 공모전 프로젝트
- 별도 GitHub 저장소와 독립 개발 공간 사용
- 기존 GROAD의 사진·GPS 기반 도로 위험 제보 서비스를 개발 기반으로 선택
- 시민의 위험·아차 사고·단순 주의 제보와 지도 확인 흐름을 우선
- 원본 소스와 DB를 보존하고 Manito의 제보 저장소·인증키·포트를 분리

## 현재 개발 기반

웹은 `apps/web`, 독립 Node API는 `services/api`에 있다. 사진 선택/촬영, 설명·분류, 현재 GPS 좌표·정확도·시각 기록, 지도 위치 선택 대체, 사진 EXIF 제거, 제보·사진 저장, 지도 마커 상세 조회 코드를 인계했다.

우왓을 Gemini 사진·대화 분석과 BM25 RAG로 업그레이드했다. 별도 제보 입력 양식 대신 대화에서 관찰·해석·확인 질문·초안·위치를 확인한 뒤 동의하여 저장한다. 운전 중에는 촬영·타이핑·화면 선택을 요구하지 않고 음성 질문 또는 정차 후 보류 흐름을 제공한다. 외부 AI에는 서버 키와 사용자 동의가 필요하며, 실제 모델·휴대폰 검증과 코드 구현 상태를 구분한다. 기관 자동 접수·회신은 미구현이다.

## 다음 개발 순서

1. 독립 개발 환경에서 제보·사진·지도 흐름 검증
2. HTTPS 시험 주소를 구성하고 실제 Android/iPhone에서 GPS·사진·오류 대체 흐름 확인
3. 관리자 검토, 중복 제보, 개인정보 처리, 감사 로그와 처리 상태 설계
4. 공식 기관 접수·회신 수단 확인 후 연결
5. 후속 AI 과제의 비교 기준과 학습·평가 데이터 분리 방법 확정

## 아이디어 선정 기준

- 첫 사용자가 명확하고 다른 고객으로 확장할 수 있어야 한다.
- 누가 어떤 가치에 비용을 내는지 설명할 수 있어야 한다.
- AI 기술이 핵심 문제 해결에 기여하고, 그 효과를 검증할 수 있어야 한다.
- 기존 서비스와 비교할 차별점 및 실제 시연 가능한 범위를 정한다.

## 아직 정하지 않은 사항

- 대회명, 규정, 마감, 발표 시간, 제출 형식
- 첫 운영기관·구매자와 후속 기능의 개발 범위
- 수익모델, 가격 가설, 검증할 고객 반응
- 팀 구성과 역할
- 기관 연계 협약·공식 접수 경로·회신 API
- 사진 분석 평가 자료·데이터 이용 조건과 후속 중복 제보 탐지 범위
- 배포 방식, 운영 비용, 일정

## 구현 전에 작성할 내용

1. 문제: 누가 언제 어떤 손실을 겪는가?
2. 근거: 인터뷰, 실제 사례, 자료 중 무엇으로 확인했는가?
3. 핵심 기능: 발표에서 처음부터 끝까지 보여줄 한 가지 흐름은 무엇인가?
4. AI: 규칙이나 일반 검색보다 유리한 이유와 직접 구현·개선하는 부분은 무엇인가?
5. 데이터: 수집 방법, 사용 권한, 품질, 학습·평가 데이터 분리 방법은 무엇인가?
6. 평가: 비교 기준, 정확도·속도·비용 등 주요 지표와 실제 사용자 확인 방법은 무엇인가?
7. 사업: 첫 구매자, 과금 단위, 도입 이유는 무엇인가?

확인되지 않은 수치나 구현하지 않은 기능은 결과로 표시하지 않는다.

연구는 초기 2차 강건성 결과보다 최종 완전격자 판정을 우선한다. 최종 결과는 H0를 기각하지 못했다. 현재 인계본에 대용량 중간 패널 10개가 없으므로 전체 재학습을 재현했다고 주장하지 않는다.
