# Manito 개발 기반 검증

검증일: 2026-11-23 (Asia/Seoul)

## 1차: 인계·범위·설정

- 원본 웹/API의 174개 파일은 인계 당시 SHA-256과 일치하며 원본을 변경하지 않았다.
- 연구 ZIP 128파일 중 126개가 내부 원본 manifest의 크기·해시와 일치한다. manifest 자체 2개는 ZIP 전체 해시로 기록했다.
- 대용량 중간 패널 10개는 원본 ZIP에도 없다. 누락 목록을 인계했고 전체 재학습 완료로 간주하지 않았다.
- 웹/API 포트는 5174/8790이며 기존 GROAD의 5173/8788과 구분한다.
- 새 내부 API 키를 생성했다. 기존 외부 서비스 키·Sites 배포 ID·DB는 복사하지 않았다.
- 원본 GROAD 제보 볼륨 `groad_reports_data`와 새 `manito-dev_reports` 볼륨이 별개임을 Docker에서 확인했다.
- 설치는 기존 pnpm 11.25.0 잠금 파일을 유지했다.
- 환경변수 예시는 빈 값만 포함하며 로컬 환경변수와 데이터가 Git에서 제외됨을 확인했다.
- setup을 재실행해도 기존 로컬 설정이 바뀌지 않았다.
- 빌드한 클라이언트 파일 23개에서 새 내부 API 키 문자열을 찾지 못했다.

## 2차: 실행·빌드·핵심 흐름

| 검사 | 결과 |
| --- | --- |
| `python scripts/check_repository.py` | 통과 |
| `node --run test` | 12/12 통과 |
| TypeScript `tsc --noEmit` | 통과 |
| `node --run build` | Vinext/Vite 빌드 통과 |
| 로컬 웹·API 상태 | HTTP 200 |
| API 무인증 요청 | HTTP 401 |
| 새 API를 통한 실제 지도 타일 조회 | PNG HTTP 200 |
| 웹 프록시를 통한 사진 제보 저장 | HTTP 201 |
| 좌표·GPS 정확도·시각 보존 | 전송한 가상 메타데이터와 일치 |
| 사진 재조회 | 저장한 PNG 바이트와 일치 |
| Manito API 컨테이너 재시작 | 제보·사진 유지 |
| 검사용 가상 제보 정리 | 생성한 검사용 기록만 삭제 |

HTTP 흐름은 `node scripts/smoke.mjs --write-report`로 확인했다. 이 쓰기 검사는 비어 있는 Manito Docker 저장소에만 사용하며 실제 시민 제보·기기 GPS 측정이 아니다. 기본 `node scripts/smoke.mjs`는 읽기 검사만 한다. 마지막 로컬 결과는 무시되는 `.local/smoke-result.json`에 저장한다.

기존 교통 단위 테스트가 대형 도로선 데이터에 의존하던 문제는 테스트 전용 fixture와 서버의 `ITS_LINK_SHAPES_PATH` 설정으로 분리했다. 해당 단위 테스트의 교통·AI 원본 응답은 모의 응답이다. 가상 도로선을 실제 데이터로 제공하지 않는다.

빌드에는 기존 Lucide 아이콘 최적화와 Leaflet CSS 이미지 경로 경고가 남아 있다. 빌드를 차단하지 않았으며 모든 브라우저·기기에서의 표시를 검증한 것은 아니다.

## 이번에 검증하지 않은 사항

- 실제 Android/iPhone의 카메라·갤러리·GPS 권한, 정확도와 지도 위치 선택 대체 흐름
- 실제 외부 AI 요약 API와 ITS 인증키를 사용하는 실시간 조회
- 기관 자동 접수·조치 회신, 운영 권한 체계
- 연구 모델 재학습·완전격자 통계 검정 재실행
- 새 운영 도메인·HTTPS·공개 배포

GitHub 자동 검사의 최종 결과는 기능 브랜치 Actions 기록을 확인한다. 로컬 통과와 원격 통과를 혼동하지 않는다.
