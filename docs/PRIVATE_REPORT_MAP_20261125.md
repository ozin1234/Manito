# 내 제보 위치와 지도 표시

새 사진 제보는 비공개 관리자 접수함에 저장하고 본인의 접수증으로 조회한다. 이 접근 범위를 유지하면서, 확인한 현장 위치가 있는 내 제보를 본인 지도에 표시한다. 다른 방문자의 지도나 공개 제보 API로 사진·내용·좌표를 배포하지 않는다.

## 사용 흐름

- 우왓에서 사진을 올리기 전에 ‘현장의 현재 위치 사용’ 또는 ‘지도에서 현장 선택’을 사용할 수 있다. 현장이 아닌 곳에서 찍은 사진에는 현재 GPS를 현장 위치로 붙이지 않는다. 선택한 위치와 GPS 오차를 표시하며 선택 해제도 지원한다.
- 사진 AI 판단 후 접수에 성공하면 위치를 접수증에 보관하고 내 지도에 ‘내’ 표시가 있는 핀을 즉시 추가한다. 지도는 해당 제보의 위치로 이동한다. AI가 탐색 탭과 다른 분야로 분류해도 제보한 분야로 이동한다.
- 위치 없이 사진만 접수하는 흐름은 유지한다. 이때는 지도에 임의 좌표를 찍지 않고 ‘위치 미등록 · 지도 표시 대기’로 표시한다.
- 이미 접수한 제보도 내 제보 상세에서 현장 위치를 등록하거나 수정할 수 있다. 지도를 누르거나 현장에서 현재 GPS를 선택하면 서버에 저장한 뒤 내 지도에 반영한다.
- 내 핀을 누르면 동일한 접수 내역·처리 현황이 열린다. 새로고침 후 접수증 조회로 위치와 핀을 복원한다. 공개 민원·이전 공개 기록·내 제보의 지도 필터를 구분한다.

GPS는 권한·HTTPS·위치 서비스가 필요하다. 정확도와 측정 시각을 포함하며 5분보다 오래된 측정이나 국내 범위를 벗어난 좌표는 사용하지 않는다. GPS 오차 반경은 측정 정확도이며 위험 반경이나 사고 범위가 아니다. 지도에서 선택한 위치도 사용자 확인 지점이며 현장 검증 결과가 아니다.

## API와 저장

`PATCH /v1/reports/{id}/location`에 `{receiptToken, location}`을 보낸다. location에는 국내 `lat`, `lng`, `locationSource: map|gps`가 필요하다. GPS이면 `locationAccuracyM`, `locationCapturedAt`도 필요하다. 접수증이 다르면 404, 좌표·측정 정보가 잘못되면 400이다.

위치만 원자적으로 갱신하고 접수 내용·비공개 속성·사진·접수증 해시·처리 상태는 유지한다. 본문·응답은 비공개 캐시 정책을 사용한다. 운영 Worker의 동일 출처 검사와 쓰기 잠금을 재사용한다. 관리자는 기존 인증된 접수함에서 보완된 좌표를 확인한다.

브라우저에는 성공 응답의 좌표·출처·GPS 정확도·측정 시각을 접수증과 함께 보관한다. 핀에 전달하는 데이터에서 비밀 접수증은 제외한다. 위치가 없는 접수증, 국내 범위 밖 좌표, 조회 권한을 확인하지 못한 제보, 다른 분야는 핀으로 만들지 않는다. 새 제보/위치 저장 도중 시작된 이전 새로고침 결과가 최신 접수증을 덮어쓰지 않도록 확인한다.

새 환경변수·의존성·DB 스키마 변경은 없다. 기존 D1/R2와 로컬 파일 저장을 재사용한다. 실행은 기존 `node --run dev`, 운영 주소는 README와 같다.

## 검증

- API: 비밀 접수증으로만 위치 수정, 잘못된 접수증·좌표·오래된 GPS 거절, 접수 내용·사진·해시·비공개 속성 보존, 관리자 좌표 반영을 검사한다.
- 클라우드 어댑터: D1(SQLite)/R2 모의 저장에서 위치 수정과 비공개 유지, 다른 쓰기 잠금 중 수정 차단을 확인한다.
- 브라우저: 격리된 로컬 서버·합성 사진·모의 AI에서 사진 접수 → 위치 없음 안내 → 지도에서 현장 등록 → 내 핀 생성 → 핀에서 처리 내역 열기 → 새로고침 후 복원을 확인했다. 제보 전 위치 선택 → 사진 접수 → 즉시 핀 2개로 증가하는 경로도 확인했다.
- 실제 휴대폰 GPS 정확도·기기 권한 팝업·현장 사진 판독 정확도는 이 모의 검증과 구분한다. 운영 관리자 접수함에 테스트 제보를 만들지 않았다. 최종 전체 테스트·빌드·운영 배포 결과는 PR에 기록한다.
