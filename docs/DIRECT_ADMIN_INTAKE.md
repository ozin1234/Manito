# 사진 제보의 관리자 직접 접수

2026-11-25 현재 구현이다. 과거 문서의 ‘최종 공개 동의 후 공개 기록 저장’은 이전 API 호환 동작이며 현재 우왓 화면에는 적용하지 않는다.

## 사용 흐름

1. 우왓에서 사진 AI 분석과 K-ROAD 관리자 접수에 동의한다.
2. 사진만 올리면 Gemini가 관찰·유형·제목·요약·제보 내용을 판단한다. 설명 입력은 받지 않는다.
3. 명확한 판단은 비공개 관리자 접수함에 바로 저장한다. 어려운 경우에만 객관식 질문을 보여주며 답변 후 판단을 마무리한다. 답이 여전히 불명확하면 추가 확인 또는 다른 사진이 필요할 수 있다.
4. 저장 성공 후 ‘내가 보낸 제보’에 접수 번호·분류·요약·접수 방식·현재 상태가 표시된다. 카드를 열면 작성된 내용과 선택 답변·AI 판단 근거·처리 단계를 확인한다.
5. `/admin`의 사진 제보 접수함에서 인증된 관리자가 사진과 내용을 검토하고 부서·상태·이력을 관리한다. 제보자는 현재 처리 상태와 전달용 안내를 조회한다.

외부 안전신문고 이동·복사·재신고 버튼은 제거했다. K-ROAD 접수함에 실제 저장된 경우만 접수 완료다. 실제 공공기관 협약, 긴급 출동, 국가 민원 시스템 연계가 완료됐다는 뜻은 아니다. 관리자 운영을 해당 기관에 맡길 수 있는 구조다.

위치는 필수가 아니다. 사용자가 현장에서 GPS를 선택하거나 지도에서 고른 위치는 포함하고, 없으면 `locationStatus: pending`, 좌표는 `null`로 저장한다. 사진·EXIF·화면 중심으로 위치를 추측하지 않는다. 위치가 없는 제보도 접수 후 내 제보 상세에서 보완할 수 있다. 현장 위치가 있는 제보는 본인 지도에 핀으로 표시한다. [내 제보 지도 구현](PRIVATE_REPORT_MAP_20261125.md)을 참고한다.

## API 계약과 호환

- `POST /v1/assistant/chat`: 새 요청은 `requestId`(UUID v4), `requestToken`(브라우저 난수 32바이트의 base64url), `submitToAdmin: true`, `allowAdminSubmission: true`, `allowAiProcessing: true`, `photoDataUrl`, `topic`을 보낸다. 선택한 `location`은 선택 사항이다.
- 객관식 답변은 같은 요청의 `sessionId`, `requestToken`, 질문/선택지 ID를 보낸다. 이전·존재하지 않는 질문은 실행하지 않는다.
- 성공 응답은 `phase: submitted`, `destination: kroad_admin`, `report`를 포함한다. `report`에는 접수 번호·방식·분류·내용·비밀 `receiptToken`이 있다.
- 같은 ID·토큰·사진의 재시도는 같은 제보와 접수증을 반환한다. 다른 사진·토큰은 거절한다. 저장 전 중간 상태를 먼저 남겨 저장 후 응답 유실 시 중복 접수를 방지한다.
- `POST /v1/reports/tracking`: `receipts: [{id, receiptToken}]`로 최대 100건씩 조회한다. 본인의 내용·현재 진행 상태만 반환하며 틀린 접수증은 `unavailable`로 표시한다. 토큰은 URL에 넣지 않는다.
- `GET /v1/admin/cases/{id}/photo`: 관리자 세션 인증이 있어야 사진을 반환한다.
- 이전 `/assistant/commit` 공개 저장 경로는 호환을 유지한다. 새 직접 접수 세션은 이 경로로 저장하거나 접수증을 조회할 수 없다.

## 접근 범위와 저장

새 사진 제보는 비공개다. 공개 지도·목록·사진·진행 안내 API에서 제외한다. 일반 방문자는 다른 사람의 ID만으로 사진·내용·진행 상태를 조회할 수 없다. 관리자 사진 경로는 인증·비공개 캐시 정책을 사용한다. 관리자 내부 메모·담당자·로그인 정보·전체 이력은 제보자 응답에서 제외한다.

서버 제보에는 접수증의 SHA-256 해시를 보관한다. 분석 세션은 재시도 복구를 위해 비공개 접수증을 보관하며 요청 토큰은 해시로 보관한다. 응답에는 서버 검증용 해시를 포함하지 않는다. 브라우저의 접수증은 비공개 내용의 조회 권한이므로 공유하거나 로그에 출력하지 않는다.

이 브라우저의 `kroad-my-reports-v1`에 성공한 접수증을 보관한다. 기기 간 동기화·계정 복구는 없다. 저장 응답 전 창을 새로 열거나 브라우저 데이터를 지우면 접수증 복구를 보장하지 않는다. 재시도 버튼은 같은 열린 요청을 이어간다.

기존 D1/R2·Node 파일 저장, 관리자 인증·상태 전이·버전 검사·쓰기 잠금을 재사용한다. 접수증 조회는 읽기이므로 다른 분석의 쓰기 잠금 때문에 차단하지 않는다. 스키마·패키지·환경변수 변경은 없다. 공개 민원 CSV·수집 데이터·지도 위치 자료·법령 원문은 변경하지 않았다.

## 실행과 환경변수

Node 24 이상에서 `node --run setup`, `node --run dev`. 웹 기본 주소는 `http://127.0.0.1:5174/`, 관리자 경로는 `/admin`이다. 관리자 설정은 `node scripts/setup.mjs --admin`을 사용한다.

기존 서버 변수 `GEMINI_API_KEY`, `UWAT_MODEL`, `KROAD_API_KEY`, `KROAD_API_URL`, `KROAD_ADMIN_USERNAME`, `KROAD_ADMIN_PASSWORD_HASH`, `KROAD_ADMIN_SESSION_SECRET`, `KROAD_PUBLIC_ORIGIN`을 유지한다. `KROAD_API_URL`은 별도 Node API를 쓰는 로컬 프록시용이다. 운영 Worker는 기존 D1/R2 바인딩과 서버 비밀을 유지한다. `LAW_API_OC`는 법령 갱신 시에만 필요하다. 키·비밀번호·접수증은 Git에 올리지 않는다.

## 검증 범위

- 자동 테스트: 명확한 사진의 무위치 접수, 객관식 선택 전 미접수·선택 후 접수, 재시도 중복 방지, 다른 사진·잘못된 토큰·구형 commit 경로 거절, 동의 누락·AI 실패·문제 없음의 미접수, 비공개 목록·사진·진행 상태 보호, 내부 메모 제외를 검사한다.
- 클라우드 어댑터: 실제 SQLite 기반 D1 모의 어댑터와 R2 모의 저장으로 같은 접수·조회·권한 동작을 실행한다. 다른 쓰기 잠금 중에도 접수증 조회가 가능함을 검사한다.
- 브라우저: 격리된 로컬 서버와 합성 사진·모의 Gemini 응답으로 사진 업로드 → 자동 접수 → 목록/상세 → 관리자 사진 확인 → 검토 중 변경 → 새로고침 후 제보자 상태 반영을 확인했다. 객관식 선택 후 자동 접수와 선택 답변 표시도 확인했다. 운영 데이터에 검증용 민원을 만들지 않았다.
- 브라우저 화면은 PC 크기에서 확인했다. 요청한 좁은 화면 오버라이드가 실제 뷰포트에 적용되지 않아 이번 모바일 화면 검증 완료로 세지 않는다. 실제 휴대폰 촬영·GPS·알림음·현장 사진 판독 정확도는 이번 검증에 포함하지 않는다.
- 전체 테스트 수·빌드·배포 결과는 해당 PR에 기록한다. 이 검증은 모의 AI의 접수 흐름 검증이며 새로운 실사진 정확도 평가가 아니다.
